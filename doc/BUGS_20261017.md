# Trivial bug review, 20261017

Base: dev a5eee25. The fixes were prepared as a patch file
(`work/bugs-20261017.diff`, not tracked) and committed together with this
document. The patch changes five files, +12/-5 lines.

## Fixes in the patch

1. `include/DataBuffer.h:50` (`push()`). `m_max_queue_size` was updated
   before the drop loop, so after a push onto a full queue it recorded
   `max_queue_blocks + 1` (1025) although the queue never holds that many
   after the push returns. The `Q=` field of `-v` and the exit summary
   could show `max=1025`. The update now follows the loop. I also added
   the missing `#include <vector>` (the header uses `std::vector` and got
   it only through `<queue>`).
2. `main.cpp:513` (`-P` parsing). `strncmp(optarg, "-", 1)` matched any
   argument starting with `-`. `-P -L 10` took `-L` as the device, selected
   the default device, and left `10` as a stray argument. It is now
   `strcmp(optarg, "-") == 0`, so `-L` and `-5` go to `parse_int()` and are
   rejected by `badarg("-P")`.
3. `main.cpp:751` (PORTAUDIO case). With `--portaudio-prefill-adapt` > 0
   and not above `--portaudio-prefill`, `adapt()` computes `cap - total <= 0`
   on every underflow and never adds silence, with no indication. A warning
   is printed next to the existing prefill messages. The condition is
   `<=`, because equal values also give `cap - total == 0`.
4. `CHANGES.md:47` and `include/StatusPrinter.h:50`. The text said the
   status line is printed "about every 100 milliseconds". The 50 ms
   `interval` is the printer thread's polling period: `print()` returns
   when no new snapshot was published. The decode loop publishes every
   `stat_rate` blocks, about 0.11 s (`ifrate / if_blocksize / 9`), so
   prints occur 100 to 150 ms apart. CHANGES.md now says that. The
   header comment "Interval between prints" now says "Interval between
   checks for a new snapshot". The existing line "Set to 50msec for
   smooth updates." is unchanged.
5. `sfmbase/AudioOutput.cpp:209` (`PortAudioOutput` constructor). The
   range check was `index >= Pa_GetDeviceCount()`. A negative index other
   than -1 would reach `Pa_GetDeviceInfo()`, which returns null, and then
   `->name` dereferences it. Not reachable from the command line now
   (`main.cpp` rejects negative values), so this is defensive: the check
   is now `index < 0 || index >= ...`.

## Looked at and left out

Non-trivial or design items (as requested):

* `Ring=` capacity comes from `outputLatency * rate`, which may differ
  from PortAudio's real blocking ring size (the handoff probe shows
  reported values about five times the suggested latency). Related
  consequence: `capacity - free` can go negative if
  `Pa_GetStreamWriteAvailable()` exceeds the estimate, and the status
  line would print a negative fill. A `std::max(0L, ...)` would hide the
  symptom but not the cause, so I left it.
* `dropped_samples` is added with `+=` per transfer in
  `AirspySource.cpp:489` and `AirspyHFSource.cpp:411`. Whether libairspy
  reports a per-transfer or a running count is unconfirmed; not changed.
* Priority-inversion risk: the UTILITY-QoS printer takes the DataBuffer
  mutex for `-v` fields.
* P4: the 10 ms adaptive silence step goes after the block that
  underflowed (an extra gap); the clamp depends on the capacity estimate;
  `-L 5` leaves little room to prefill.
* The `--portaudio-prefill` help text, README.md:147, and the CHANGES.md
  clamp bullet say "use with `-L 8` to `-L 10`", which the probe figures
  may contradict. That is a content decision for the author.
* `prime()` prints "prefill clamped" even when only the adapt cap was
  clamped. The message is imprecise but harmless.

Trivial but outside the recent work, not changed:

* `main.cpp:738-751`: the "playing audio to PortAudio ... name ''" lines
  are printed before the `if (!(*audio_output))` check, so a failed open
  prints an empty device name before the error.
* `include/AudioOutput.h:91-93`: the `SndfileOutput` comment names a
  parameter `sf_info`, but the parameter is `format`.
* `include/Source.h:62`: "Return name of opened RTL-SDR device." is stale
  (the accessor serves all sources).
* `DataBuffer::push()` prints an overflow message on every push while
  overflowing. Rate limiting is a behavior change.

Checked and found correct: `StatusPrinter` thread start/stop and final
print, stereo event replay (unsigned subtraction wraps correctly),
`Telemetry` defaults for non-PortAudio outputs, `print_summary()` after
`output_close()` (atomics only), `adapt()` guards against negative
`add`/`cap`, `write()` first-block underflow handling, `-L` and prefill
range checks (100 ms maximum matches the help and README).
