# FIR Low-Pass Filters — VOLK Rewrite (2026-07-25)

Rewrite of `LowPassFilterFirIQ` and `LowPassFilterFirAudio`
(`include/Filter.h`, `sfmbase/Filter.cpp`) to compute each output as a single
VOLK dot product, replacing the hand-rolled warm-up + symmetry-folded loops.
Done on branch `dev-lpf-volk`, cut from `dev` at `83bfcd3`.

## Executive summary

- **What changed.** Both FIR low-pass classes now build one contiguous history
  buffer per block (`[state | input]`) and emit each output sample with one
  `volk_..._dot_prod` call over `order + 1` taps. The coefficient vector is
  stored **reversed** once at construction so the dot product is a true
  convolution. The former two-region (warm-up / steady-state) structure and the
  linear-phase symmetry fold are both gone. Net **−11 lines**, and the two
  `n < order` / `n >= order` state-update branches collapse to one `std::copy`.
- **Kernels.** IQ path (complex samples, **real** taps):
  `volk_32fc_32f_dot_prod_32fc`. Audio path (real × real):
  `volk_32f_x2_dot_prod_32f`. VOLK 3.3.0.
- **A latent bug is fixed for free.** The old warm-up loops summed taps
  `j = 1 … order` and silently **dropped the `j = 0` tap**
  (`coeff[0] · in[p]`) on the first `order` output samples of *every* block.
  The dot product always covers all `order + 1` taps, so the omission is gone.
  It was nearly harmless only because every shipped coefficient table is a
  heavily-tapered windowed sinc whose edge tap is ≤ −67 dB (exactly 0 for the
  3-tap IF filter used by the default/wide FM presets). See §2.
- **Measured difference vs `dev`.** Decoding three IQ files
  (`test-files/`) through both binaries: max per-sample audio difference
  **3–5 × 10⁻⁷** (1–2 float32 ULP), signal-to-difference ratio **≈ 134 dB** on
  all three — the pure float re-association floor, ~36 dB below the 16-bit
  audio floor. Inaudible. See §3.
- **CPU.** Whole-pipeline user CPU for the 20 s piano decode drops from
  ~0.73 s to ~0.67 s, **≈ 8 % less**, consistent across 5 interleaved reps.
  See §4.
- **Recommendation.** Merge to `dev` after a listening check. The change is a
  simplification, a small speedup, and a bug fix, with no audible or
  measurable regression. See §6.

## 1. Design

### 1.1 Index algebra

Let `x` be the virtual stream: the previous block's `order` state samples
(`x[−order … −1]`) followed by this block's input (`x[0 … n−1]`). The filter
computes

```
y[p] = Σ_{j=0}^{order} coeff[j] · x[p − j]
```

Build one contiguous buffer `ext = [state | input]` of length `order + n`, so
`ext[m] = x[m − order]`. For output `p`, the oldest-to-newest window is
`ext[p … p + order]` (always in bounds: `p + order ≤ (n−1) + order = size−1`).
Substitute `i = order − j`:

```
y[p] = Σ_{i=0}^{order} coeff[order − i] · ext[p + i]
```

So the dot product runs the window `ext.data() + p` against the **reversed**
coefficients `coeff[order − i]`. The reversal is done once in the constructor
(`std::reverse_copy` into a `volk::vector<float>`), never per sample. Every
shipped table is symmetric (`coeff[k] == coeff[order − k]`), so the reversal is
numerically a no-op today, but it is computed generically for robustness
against a future non-symmetric design.

This one loop replaces both the old warm-up region (`p < order`, drawing from
state) and the steady-state region — every `p ∈ [0, n)` uses the same
`ext.data() + p` scheme, so it structurally **cannot** omit a tap.

### 1.2 State, downsampling, empty input

- **State update** collapses to `std::copy(ext.end() − order, ext.end(),
  state.begin())`. The last `order` samples of `ext` are the next block's
  state whether `n < order` (state tail + all input) or `n ≥ order` (input
  tail), removing the old two-branch update.
- **Downsampling** (`m_downsample`/`pstep`) and the cross-block phase
  `m_pos = p − n` are preserved verbatim; only the inner computation changed.
  (Every current call site passes `downsample = 1`, so the decimating path is
  dead today but still supported.)
- **`n == 0`** still short-circuits before the `resize`, both to avoid the
  unsigned underflow in `(n − p + pstep − 1)` and to leave `m_state` untouched.

### 1.3 Containers and alignment

- New member `m_coeff_reversed` is a `volk::vector<float>` — the fixed operand
  of every dot product, so it is worth aligning once.
- New member `m_scratch` (the `ext` buffer) is a `volk::vector` of the sample
  type; `resize(order + n)` each call touches only the tail after the first
  block since block sizes are stable in this pipeline.
- The moving operand `m_scratch.data() + p` carries an arbitrary (generally
  unaligned) offset. VOLK's dot-product dispatch handles unaligned pointers —
  the same pattern `MultipathFilter` already relies on
  (`sfmbase/MultipathFilter.cpp:149` hands VOLK `m_state.data() + m_state_pos +
  1` every call). No manual alignment handling is needed.
- No new includes: `Filter.h` → `SoftFM.h` → `<volk/volk_alloc.hh>` →
  `<volk/volk.h>` already makes both `volk::vector` and the kernels visible.

## 2. The warm-up `coeff[0]` bug (now fixed)

The old warm-up loops (`Filter.cpp` on `dev`, IQ lines 59–68, audio 126–135)
ran, for each output `p < order`:

```cpp
for (j = p+1; j <= order; j++) y += m_state[order+p-j] * m_coeff[j];  // state
for (j = 1;   j <= p;     j++) y += samples_in[p-j]    * m_coeff[j];  // input
```

Together these cover `j = 1 … order`. **`j = 0` is never touched**, so the tap
that multiplies the current input sample, `coeff[0] · samples_in[p]`, was
dropped — for the first `order` outputs of *every* block (with `downsample = 1`
and `n ≥ order`, the state update always leaves `m_pos = 0`, so the warm-up
region recurs at the start of each block, not just at file start). The
steady-state fold *did* include it (via the `k = 0` term
`(in[p] + in[p−order]) · coeff[0]`), so the two regions computed different
sums.

**Why it was nearly harmless:** every coefficient table in
`FilterParameters.cpp` is a Type-I linear-phase windowed sinc whose edge tap is
tiny relative to the passband:

| coefficient set | order | coeff[0] / center | note |
|---|---|---|---|
| `delay_3taps_only_{iq,audio}` | 2 | 0 exactly | FM IF filter, default/wide presets → bug was a no-op |
| `jj1bdx_48khz_fmaudio` (pilot-cut, every FM decode) | 126 | 1.5 × 10⁻⁷ | ≈ −136 dB |
| `jj1bdx_am_48khz_*` | 126–254 | ~6 × 10⁻⁶ … 1.1 × 10⁻⁵ | |
| `jj1bdx_nbfm_48khz_*` | 126 | ~3 × 10⁻⁶ … 2.6 × 10⁻⁵ | |
| `jj1bdx_fm_384kHz_{narrow,medium}` (IF) | 126 | ~3 × 10⁻⁶ … 8.5 × 10⁻⁶ | |
| `jj1bdx_cw/ssb_48khz_*` | 2048 | 3 × 10⁻⁵ … 4.3 × 10⁻⁴ | steepest edge |

So the dropped term was between roughly −140 dB and −67 dB of full scale. This
is a property of the current filter *designs*, not any protective logic; a
future steeper/shorter filter with a non-negligible edge tap would have exposed
it. The rewrite closes it.

## 3. Numerical difference vs `dev`

Both binaries were built identically (`-O3 -ftree-vectorize`, no
`-ffast-math`), the only difference being `include/Filter.h` +
`sfmbase/Filter.cpp`. Each IQ file was decoded to a FLOAT WAV (`-G`, default FM
preset, `-q`) with both, and the two audio outputs compared sample-for-sample.

| file | length (48 kHz) | max abs diff | SNR (signal / difference) | samples differing |
|---|---|---|---|---|
| `piano_iqtest.wav` | 959 899 | 2.98 × 10⁻⁷ | 134.3 dB | 90.7 % |
| `joakfm-…-iq.wav` | 2 879 899 | 2.98 × 10⁻⁷ | 134.4 dB | 91.4 % |
| `interfm-…-iq.wav` (real multipath) | 4 799 899 | 4.77 × 10⁻⁷ | 134.3 dB | 89.1 % |

The difference is the predicted floating-point re-association floor: the SIMD
dot product sums the `order + 1` terms in a different order than the old
symmetry fold, perturbing nearly every sample by 1–2 ULP. The `coeff[0]`
warm-up fix (§2) adds at most a −67 dB term on the first `order` samples of
each block, swamped by that floor. The result is the same ~134 dB on all three
files — ~36 dB below the 16-bit floor (98 dB) and below the 24-bit
quantization floor as well. The multipath file behaves identically to the
clean ones, confirming the change is benign on a real dispersive signal.

Bit-exact parity with `dev` is not achievable from a VOLK rewrite either way,
since re-association alone breaks it throughout the signal; a tolerance check
(SNR / max-abs-diff) is the right regression test, not `diff`.

## 4. CPU

`filesource` paces itself to real time, so wall clock is meaningless; user CPU
time is the signal. Five interleaved reps (dev, volk, dev, volk, …) of the 20 s
`piano_iqtest.wav` decode, `-G` FLOAT out, `-q`:

| build | user CPU (s), 5 reps | min |
|---|---|---|
| `dev` | 0.72, 0.73, 0.73, 0.73, 0.73 | 0.72 |
| `dev-lpf-volk` | 0.67, 0.67, 0.67, 0.67, 0.68 | 0.67 |

**≈ 8 % less whole-pipeline user CPU**, tightly clustered. This is the total
decode (demod, PLL, resampler, multipath filter, etc.); the LPFs are one stage,
so their own speedup is larger than the pipeline figure. The default FM preset
uses the 3-tap IF filter, so most of the LPF work measured here is the
order-126 pilot-cut audio pair. VOLK wins despite doing ~2× the multiplies of
the old symmetry fold (`order + 1` taps vs `~order/2` folded), because the
dot-product kernel vectorizes and the fold did not.

## 5. Reproduction

```sh
# binaries: dev baseline via a worktree, rewrite on the branch
git worktree add /tmp/wt-dev dev
cmake -S /tmp/wt-dev -B /tmp/wt-dev/build && cmake --build /tmp/wt-dev/build
cmake --build build           # branch dev-lpf-volk

# decode both (default FM preset), 384 kHz FLOAT baseband IQ
decode() { "$1" -t filesource \
  -c freq=82000000,srate=384000,filename="$2" -G "$3" -q; }
decode /tmp/wt-dev/build/airspy-fmradion test-files/piano_iqtest.wav dev.wav
decode ./build/airspy-fmradion           test-files/piano_iqtest.wav volk.wav

# compare: max abs diff and signal/difference SNR (expect ~134 dB)
python3 -c 'import soundfile as sf,numpy as np; \
a=sf.read("dev.wav")[0]; b=sf.read("volk.wav")[0]; n=min(len(a),len(b)); \
d=(b[:n]-a[:n]).astype("f8"); \
print(np.max(np.abs(d)), 10*np.log10((a[:n]**2).sum()/(d**2).sum()))'

# CPU: interleave reps, take minima (filesource is real-time paced → use user CPU)
```

## 6. Recommendation

Merge `dev-lpf-volk` to `dev` after a listening check. The rewrite is:

- **simpler** — one dot-product loop, no warm-up/steady-state split, no
  symmetry-fold branch, single-`std::copy` state update, −11 lines;
- **correct** — fixes the warm-up `coeff[0]` omission;
- **faster** — ~8 % less whole-pipeline user CPU, more on the filter stages;
- **benign** — 134 dB below signal on clean and multipath inputs alike, well
  under the 16-bit floor.

No behavioral knob is added and no on-air tuning changes, so per the project
workflow it still wants a field/listening pass on `dev` before `main`, but the
risk surface is small. The one thing worth a spot-check on the air is any
preset that exercises a filter with a larger edge tap (CW/SSB, AM narrow),
where the warm-up fix changes slightly more than the round-off floor — though
still far below audibility.
