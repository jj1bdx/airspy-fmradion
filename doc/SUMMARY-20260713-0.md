# Summary of changes: 20260505-0 to 20260713-0

This document summarizes all changes between tag `20260505-0` and commit
`2df232b` (released as `20260713-0`): nine commits, 34 files changed,
+1363/−430 lines.

`SoftFM.h` type aliases. It consists of robustness/hardening fixes, one

## 1. W1-W7 and X1-X8 robustness fixes

See [doc/FIXES_CLAUDE_20260610.md](FIXES_CLAUDE_20260610.md) and
[doc/FIXES_CLAUDE_20260610_2.md](FIXES_CLAUDE_20260610_2.md) for full
details. These fifteen fixes continue the static-analysis-driven
hardening effort (following V1-V41 of the previous release). All are
defensive; none change DSP behavior for valid configurations. The main
classes of issue:

- **Null-pointer crashes on partial initialization**: `AirspyHFSource::stop()`
  called `airspyhf_stop()` and `m_thread->join()` unconditionally (W1);
  both Airspy variants' `callback()` used `m_buf` without a null check
  (W5).
- **Validation ordering and range checks**: `hf_att` was narrowed to
  `uint8_t` before its bound check, making the check dead code (W2);
  Airspy HF frequency now rejects values below 1000 Hz (W3);
  `sampleRateIndex` is now bounds-checked before indexing `m_srates[]`
  in both Airspy sources (W4/X3).
- **Assert-bypass buffer overrun under `-DNDEBUG`**: the resampler input
  limits (`IfResampler::max_input_length` = 65536) were enforced only by
  `assert()`. `RtlSdrSource` and `FileSource` block lengths are now
  clamped to 65536 at configuration time, closing a heap-corruption path
  in r8brain when asserts are compiled out (X1).
- **Pathological `-r` ppm values**: `-r -1000000` zeroed `ifrate`, and
  `-r -999999` caused a confirmed SIGSEGV inside r8brain via integer
  overflow at extreme upsampling ratios; both are now rejected, with a
  new 64x maximum upsampling-ratio guard (X2).
- **Resource and shutdown hygiene**: `ppsfile` is now closed on exit (W7);
  `PortAudioOutput::output_close()` is idempotent and safe after
  `Pa_Terminate()` (X5); the main loop now checks
  `audio_output->write()`'s return value and shuts down cleanly on write
  failure instead of continuing (X6).
- **Unbounded queue growth**: `DataBuffer<T>::push()` is now bounded at
  1024 blocks with a drop-oldest policy and a dropped-block counter (X7).
- **Minor**: NaN in the ppm status display when `tuner_freq` is 0 (X8);
  `size_t` loop variables in three `FmDecode.cpp` helpers (W6);
  `AirspySource::start()` returns `true` instead of `*this` (X4).

User-visible effects: stricter option validation (some previously
accepted `-r`, `freq`, `hf_att`, and `blklen` values are now rejected or
clamped with a stderr warning), and a new fatal exit path on audio
write failure.

## 2. DataBuffer overflow warning on every dropped block

Follow-up to X7 (see
[doc/FIXES_CLAUDE_20260610_2.md](FIXES_CLAUDE_20260610_2.md)). The
rate-limiting condition on the overflow warning in
`include/DataBuffer.h` was removed as redundant; the warning now prints
on every dropped block:

```
DataBuffer: queue overflow, dropped blocks = {}
```

This makes sustained consumer overload maximally visible. The
`fmt::println` call remains outside the mutex; verified race-free under
ThreadSanitizer.

## 3. RtlSdrSource: sync to async streaming rewrite

The largest functional change of the release. See
[doc/RTL_READ_ASYNC_20260713.md](RTL_READ_ASYNC_20260713.md) for the
full analysis.

`RtlSdrSource` now streams with `rtlsdr_read_async()` instead of a loop
of blocking `rtlsdr_read_sync()` calls. The source thread blocks inside
librtlsdr's libusb event loop, which keeps 15 USB transfer buffers in
flight and invokes a callback for each filled buffer; the callback
converts the offset-binary bytes to `IQSampleVector` and pushes directly
into `DataBuffer` (the per-block staging vector is gone).

Shutdown correctness fixes included in the same commit:

- `callback()` never checks the stop flag; it keeps pushing until the
  async loop is actually canceled, so a consumer blocked in
  `DataBuffer::pull()` always wakes to observe the stop flag.
- `run()` calls `push_end()` unconditionally when streaming ends, so the
  main loop always terminates (fixes a SIGINT shutdown hang).
- `stop()` is idempotent, and the destructor calls `stop()` before
  `rtlsdr_close()`, so device close cannot race a live async loop.

The practical benefit is dropout robustness, not CPU or throughput: the
in-flight buffers absorb roughly 77-307 ms of scheduling jitter
(depending on sample rate and block length) that previously had only the
sub-millisecond on-chip FIFO, and a short read is no longer a fatal
error.

## 4. Comment style conversion

Purely cosmetic (see
[doc/COMMENT_STYLE_20260711.md](COMMENT_STYLE_20260711.md)). C-style
`/* ... */` comments were converted to C++ `//` style (Doxygen blocks to
`///`) across 15 files. Verified comment-only by two independent comment
strippers producing identical digests of the stripped output for every
file. No functional impact.

## 5. Developer tooling: CLAUDE.md split into project skills

`CLAUDE.md` was reduced to critical constraints plus pointers to four
new skill files under `.claude/skills/` (`build`, `format`,
`architecture`, `commit-messages`). `.gitignore` gained
`!.claude/skills/build/` so the `build/` ignore pattern does not exclude
the new directory. No effect on the built binary.

## 6. {fmt} 12.2.0

`CMakeLists.txt` bumps the CMake-fetched `{fmt}` library from 12.1.0 to
12.2.0 (FetchContent `GIT_TAG` pin). No source changes were needed; no
runtime behavior change expected.
